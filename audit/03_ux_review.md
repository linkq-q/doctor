# 03 - 用户体验分析 (UX/UI Review)

> 审计日期：2026-03-13

---

## 概述

本项目有两类用户体验需要评估：
1. **编辑器工具用户**（技术美术 / 开发者）：使用 RenderAuditWindow、AnimAuditWindow、AnimalSystemSetupWizard
2. **游戏最终用户**（玩家）：体验动物生态模拟系统

---

## A. 编辑器工具 UX 分析

### 1. RenderAuditWindow（渲染审计窗口）

**用户流程**：
```
打开窗口 → 指定 Config → 点击扫描 → 查看结果 → 过滤/搜索 → 导出报告
```

| 维度 | 评分 | 说明 |
|------|------|------|
| 流程完整性 | ★★★★☆ | 扫描→结果→导出流程闭环 |
| 信息反馈 | ★★★☆☆ | 有扫描中/完成提示，缺少进度条 |
| 错误状态 | ★★☆☆☆ | Config 未配置时无明确引导 |
| 可发现性 | ★★☆☆☆ | 无菜单入口路径记录，新用户难以找到 |

**摩擦点**：
- 用户需手动创建 RenderAuditConfig 资产并拖入窗口，无"一键创建默认配置"按钮
- 扫描过程无进度条，大场景时用户不知道要等多久
- 报告输出路径固定在 Config 中，无法在窗口中临时修改
- 搜索和过滤功能存在但未做持久化，窗口重开后重置

**改进建议**：
- 添加 `[MenuItem]` 注册到 Unity 菜单栏
- 提供"创建默认 Config"按钮
- 添加 EditorUtility.DisplayProgressBar 进度反馈
- 结果列表添加双击定位到场景对象功能

### 2. AnimAuditWindow（动画审计窗口）

**用户流程**：
```
打开窗口 → 扫描项目 → 选择物种 → 查看分类 → 生成报告/控制器
```

| 维度 | 评分 | 说明 |
|------|------|------|
| 流程完整性 | ★★★★☆ | 扫描→分类→生成完整管道 |
| 信息反馈 | ★★★☆☆ | 有扫描结果展示，缺少实时预览 |
| 错误状态 | ★★☆☆☆ | 无动画时无"空状态"引导 |
| 可发现性 | ★★★☆☆ | 中文标签对目标用户友好 |

**摩擦点**：
- 物种列表为纯文字，无法预览对应的动画剪辑
- 生成控制器后无"定位到生成文件"的跳转
- 缺少 Undo 支持，生成操作不可撤回
- Rules 资产自动创建路径硬编码为 `Assets/Editor/AnimTools/AnimNamingRules.asset`

### 3. AnimalSystemSetupWizard（动物系统设置向导）

**用户流程**：
```
打开向导 → 拖入预制体 → 点击生成 → 创建场景对象 + Config 资产
```

| 维度 | 评分 | 说明 |
|------|------|------|
| 流程完整性 | ★★★☆☆ | 一键设置，但缺少后续步骤引导 |
| 信息反馈 | ★★☆☆☆ | 无执行结果摘要 |
| 错误状态 | ★★☆☆☆ | 预制体为空时无提示 |
| 可发现性 | ★★★☆☆ | 中文界面直观 |

**摩擦点**：
- 未检查场景中是否已存在 SpawnManager/Pool，重复执行会创建多个
- 默认值基于名称匹配（butterfly, crawler, rabbit, fox），新物种类型无法自动配置
- 无法批量导入预制体（只支持逐个拖入）

## B. 游戏运行时 UX 分析

### 1. 动物行为体验

| 动物 | AI 复杂度 | 行为自然度 | 视觉反馈 |
|------|-----------|-----------|----------|
| 兔子 | 3 状态 | ★★★☆☆ 基本自然，但 Idle/Wander 切换略显机械 | 有动画驱动 |
| 狐狸 | 3 状态 | ★★★★☆ 巡逻→观察→追击链条感较好 | 有动画驱动 |
| 爬虫 | 2 状态 | ★★★☆☆ 渐隐消失效果有趣 | MaterialPropertyBlock 透明度 |
| 蝴蝶 | Perlin 噪声 | ★★★★☆ 飘逸自然的飞行感 | Lerp 平滑移动 |

**问题**：
- 动物之间缺少交互行为（狐狸追兔子的视觉反馈不够明确）
- 被追的兔子在逃跑后没有"惊慌"到"安全"的过渡状态
- 蝴蝶群体行为缺少避障（可能穿墙）
- 动物生成时无出现效果（直接 pop-in）

### 2. 空状态与边界处理

| 场景 | 当前处理 | 改进建议 |
|------|----------|----------|
| 无动物存在 | 无视觉提示 | 添加"等待生成"提示或空场景引导 |
| 所有 Zone 满员 | 静默停止生成 | Debug 日志提示 |
| Player 超出所有 Zone | 远处动物休眠 | 可添加远处动物群体模拟剪影 |
| NavMesh 不可达 | 降级为直接移动 | 行为正确但可能导致穿墙 |

### 3. 加载态与反馈机制

| 操作 | 是否有加载反馈 | 备注 |
|------|--------------|------|
| 渲染审计扫描 | 部分（有状态标记） | 缺少进度百分比 |
| 动画资产扫描 | 无 | 同步执行，可能卡顿 |
| 对象池预热 | 无 | 游戏启动时可能有帧率骤降 |
| 控制器生成 | 无 | 需要等待 AssetDatabase 刷新 |

### 4. 移动端适配

**当前状态**：未做任何移动端适配

- 编辑器工具本身不需要移动端适配（Editor-only）
- 游戏运行时部分：
  - DebugHUD 使用 OnGUI，在高 DPI 屏幕上文字过小
  - 无触控输入适配（假设 Camera.main 位置已知）
  - Physics.OverlapSphere 半径为固定值，未适配不同屏幕比例
  - 对象池容量和生成密度未考虑移动端性能限制

## C. 用户流程摩擦点总结

### 编辑器工具（开发者视角）

```
摩擦点 1: 首次使用门槛高
  → 无 README、无内置帮助、无工具提示
  → 需要手动创建配置资产才能开始使用

摩擦点 2: 操作反馈不足
  → 长时间操作无进度指示
  → 成功/失败后缺少结果摘要弹窗

摩擦点 3: 结果不可操作
  → 渲染审计发现的问题无法点击跳转到对应对象
  → 动画报告无法直接打开关联的动画剪辑

摩擦点 4: 配置管理零散
  → 多个 ScriptableObject 分散在不同路径
  → 无统一的"设置面板"或"仪表盘"
```

### 游戏运行时（玩家视角）

```
摩擦点 1: 缺少入场体验
  → 动物直接弹出，无生成动效
  → 进入场景时需等待池预热

摩擦点 2: 缺少交互性
  → 玩家仅为观察者，无法与动物互动
  → 无拍照、喂食、驯化等互动机制

摩擦点 3: 缺少环境氛围
  → 无天气系统、昼夜循环影响动物行为
  → 无音效系统（动物叫声、环境音）

摩擦点 4: 信息展示局限
  → DebugHUD 面向开发者而非玩家
  → 无"图鉴"或"物种信息"玩家面板
```

|--------|--------|----------|--------|

| Config 一键创建 | 开发者 | 低 | P0 |

| 审计结果可点击跳转 | 开发者 | 中 | P1 |
| DebugHUD 改为玩家友好 UI | 玩家 | 中 | P1 |
| 对象池预热进度提示 | 玩家 | 低 | P1 |
| 动物交互系统 | 玩家 | 高 | P2 |
| 统一配置仪表盘 | 开发者 | 中 | P2 |
| 音效系统集成 | 玩家 | 中 | P2 |
| 移动端 UI 适配 | 玩家 | 中 | P2 |
